**Full backend test suite** (`apps/api`): `npm test --runInBand` = 104/104 passing across 19 suites (unit, schema/model, DB-repository integration against a real `mongodb-memory-server` replica set, and HTTP/Supertest integration against the actual Express app) — see `apps/api/README.md` for the breakdown and commands. (Was 77/77 before the admin-dashboard stage added analytics/moderation-queue/payment-attempt/AI-oversight endpoints, then 88/88 before this stage added related-products/review-summary/LLM-provider coverage.) Under Jest's default parallel workers, this many concurrent `mongodb-memory-server` replica sets can occasionally flake with an unrelated-looking HTTP parse error in this sandboxed environment — confirmed as resource contention, not a defect, since it never reproduces with `--runInBand`.

**Admin web app test suite** (`apps/admin`): `npm run test --workspace=@shopsphere/admin` = 29/29 passing across 11 Vitest/RTL files — see `apps/admin/README.md`.

This stage also fixed one cross-cutting backend bug with no connection to the admin UI itself: Express 5's `req.query` getter recomputes a fresh object from the raw URL on every access rather than caching it, so the prior "mutate `req.query` in place" validation workaround (`src/http/middleware/validate.ts`) silently discarded every Zod default/coercion the moment a controller re-read `req.query` — invisible before now only because numeric query strings happen to coerce correctly in arithmetic. Fixed by shadowing `req.query` with `Object.defineProperty` instead; this affects every endpoint using `validate('query', ...)` with defaults, not just the new analytics ones.
